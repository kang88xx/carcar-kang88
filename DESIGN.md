## Product goals
Find the current parking location immediately. Save with floor and zone taps plus explicit confirmation. Share only through authorized membership. No automatic location inference or paid OCR.

## Personas and jobs
Two to three family members sharing a car, often with one hand in a dim underground parking garage. Prioritize large text, predictable controls and clear save outcomes.

## Information architecture
Welcome/Google sign-in → register one new vehicle or join the owner's invitation → home, history, family, settings. A received invitation joins with one explicit tap on the first card after sign-in. Home opens parking form and, only after the first record, a widget guide banner. The guide dialog has only a close button and no settings link; iOS home-widget installation remains an explicit system action. Camera OCR fills editable suggestions. Family owns invitations and membership controls; the invite sheet leads with link sharing and never displays the raw code (코드 복사 copies it). Settings owns apartment configuration, device display and privacy.

## Design principles
Location first; one primary action per screen; explicit server confirmation; plain language for errors; distinguish local demo from connected account at all times. Owner principle (2026-11-11): prefer removing over adding; ease and intuitiveness come first.

## Visual language
Canvas #F5F7FA; slate ink #1E293B for text; brand blue #2563EB for primary pill buttons, the profile control, focused fields, progress, toggles and the Material primary (pin icon tone, 2026-11-10); deep blue #1D4ED8 only as the pin's ground shadow; muted slate #526176; hairline #E2E8F0; pale blue highlight #DBEAFE for the selected tab, 최근 badge and guide step numbers; blue tint #E8EFFB for the hero location card and shared-vehicle card; deeper tint #CBDCF8; info #EFF6FF for notices; soft #EEF2F6 for secondary pills and chips. Error colors remain #FFEDE7/#95452D. Muted text has at least 5.17:1 contrast on white, canvas, soft, tint and highlight surfaces; white on accent is 5.17:1 and ink on highlight is 11.99:1. Cards are white with no border, 24–28px radius; every button and chip is a full pill. Only NotoSansKR Regular (400) and Bold (700) ship, so page headlines are Regular with tight tracking, the home greeting is small muted supporting text, and labels, buttons and chips are Bold; nothing declares 500/600. Headlines, sheet titles and tab labels clamp text scaling at 1.3 so Korean words do not break mid-syllable. Small muted group labels sit on the canvas above grouped cards. Ink on the tint uses ≥.78 alpha. Material rounded icons. No external image or font request required. Motion 180–250ms respecting reduced motion.

## Accessibility
Target WCAG AA. Minimum 48 logical-pixel hit targets, semantic labels on icon controls, visible keyboard focus, form labels and validation, scrollable forms, no color-only status. Allow text scaling and reduced motion.

## iOS footer spacing correction · 2026-11-06

Keep the four destination names and 72px navigation height, but use 12px outer horizontal margins, 8px bottom margin, a 28px corner radius, 22px icons and 11px labels with 1.2 line height. Parking group headings use 14px Bold and choices 15px Bold with 48px tap heights. On iPhone the spot field opens the numbers-and-punctuation keyboard. Other sheets share balanced header insets and bottom content padding.

## Interaction states
Explicit loading and retry; first-car empty state only after a successful load with zero vehicles; a failed first load shows a retry empty state (주차 위치를 불러오지 못했어요 / 다시 시도) instead; stalled requests end as errors after 12s (load) and 15s (save); no-record state; no-history search result; server error preserves draft; no save success before acknowledgment; camera rejection falls back to manual entry. Demo records persist locally under a separate key. Logout clears native snapshots; a same-user app restart keeps them. Only the sign-in button that was pressed shows progress. Error banners use one icon (error_outline) for every error; the generic copy is '연결이 원활하지 않아요. 잠시 후 다시 시도해 주세요.' Haptics: a selection click when a floor or zone chip changes in the parking sheet and a success haptic only after a confirmed save; nothing else vibrates.

## Content voice
Korean first. Short helpful sentences. Use '주차 기록', '가족 초대', '위치 확인'. Show device-local time with the exact hour and minute: on home and history, today and yesterday read 오늘 HH:mm / 어제 HH:mm, other days M월 d일 HH:mm, and other years yyyy년 M월 d일 HH:mm. First-car card copy is '가족 차에는 받은 초대로 참여해요.', or '가족 차의 주차 위치를 함께 봐요.' when an invitation was received (no forced line breaks). Never imply that a demo invite or local notification is real family synchronization/push.

## Implementation constraints
Flutter shared UI, Supabase production repository and isolated local demo repository. Secure native session storage. Native on-device OCR; no photo upload. Snapshot widgets show the saved parking record’s created_at (snapshot key updatedAt), labelled 기록; never describe it as a screen refresh or synchronization time. Use device local time with M월 d일 HH:mm 기록, including the year for records outside the current year. Widgets keep this format while the app uses the 오늘/어제 words above; the rule that a zone or spot value already ending in its unit (구역, 번) gets no second unit is the same in the app and the widgets. Missing or invalid times are identified explicitly, and demo snapshots retain a 체험 marker. macOS required for signed iOS/TestFlight verification. Plate uniqueness is enforced by the server at registration, with no separate availability step in the app (the server check still reveals only a boolean); membership requires an owner-issued invite. Icon changes follow confirmed parking state and run when the app is active: automatically on Android, and on iPhone only on devices where the per-device switch (off by default) is on, because iOS shows its own notice on every change. Never present an icon update or a widget instruction as successful home-widget installation.

## Pin icon and blue tone · 2026-11-10

The user chose design direction A (자리 핀) from three icon studies. The launcher icon is a white map pin on brand blue #2563EB holding the car silhouette; the eleven floor icons keep the same pin and put the floor label (F1–F5, B1–B6) inside the pin head in brand blue. The in-app brand mark (`PinMark`) draws the same geometry, so the home header and desktop sidebar show the car pin by default and the parked floor as soon as a server-confirmed record exists; the launcher icon follows under its existing conditions (supported platform, active app, native success), so the two can differ briefly. Since 2026-11-11 an iPhone follows only while its per-device switch is on (default off), so there the header pin can show a floor while the launcher keeps the default pin. Only floors with a launcher icon appear in the header; otherwise the car pin stays. The 36px header label is decorative (about 8px); the location card remains the readable floor display and the mark's semantics carry the floor. Android 13+ themed icons get a separate monochrome layer with the label knocked out of the pin.

Tone: primary pill buttons, the profile control, focused field borders and progress indicators move from slate ink to brand blue; slate stays for text, chips, the tab bar icons and the snack bar. White on #2563EB is 5.17:1. Native widgets and Live Activity keep their slate/pale-blue scheme until a separate native pass. Generators: `ios/Runner/LauncherIconSources/generate.cjs` (default + floor pins for iOS, Android and web) and the hand-maintained Android adaptive vector; the Pillow floor generator was removed.
