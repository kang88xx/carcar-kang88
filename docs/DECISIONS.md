## 쉬운 사용 우선 정리 · 2026-11-11

사용자가 2026-11-11에 정한 내용과 같은 날 함께 반영한 구현 변경이다. 각 항목 끝에 이유를 한 줄로 적는다. 같은 날 TestFlight 1.0.1 (15)로 배포해 App Store 업데이트 심사에 제출했다. 실기기 검증 완료를 뜻하지 않으며, 공개된 1.0 (13)에는 포함되지 않는다.

- **앱 전체 원칙:** 더하기보다 빼기를 먼저 검토하고, 쉽고 직관적인 사용을 우선한다. 이유: 가족 누구나 어두운 지하 주차장에서 한 손으로 쓰는 앱이라 단계·문구·설정이 늘수록 기록과 확인이 늦어진다.
- **iPhone 층수 앱 아이콘은 기기별 스위치, 기본 꺼짐.** 설정 → 이 기기에서 보기 → `주차 층수 앱 아이콘`을 켠 iPhone만 층이 바뀔 때 아이콘을 바꾼다. 꺼진 기기는 기본 아이콘을 유지하고, 업데이트 전에 층수 아이콘이 적용돼 있던 기기는 기본 아이콘으로 한 번 되돌린다. 선택은 계정·차량이 아니라 기기에 저장한다(`carcar.floor_icon.enabled`). Android는 지금처럼 자동이다. 홈 헤더 핀의 층 표시는 스위치와 무관하게 유지한다. 이유: iOS는 아이콘이 바뀔 때마다 앱이 숨길 수 없는 시스템 확인 창을 띄운다. 2026-11-02·2026-11-10의 'iOS도 자동 전환' 항목을 대체한다.
- **홈·이력의 기록 시각 표기:** 오늘은 `오늘 16:41`, 어제는 `어제 19:34`, 그 외는 `11월 9일 05:20`, 다른 해는 `2025년 11월 9일 05:20`. 날짜는 24시간 간격이 아니라 기기 달력 기준이고 시·분은 항상 그대로 보인다. 초대 만료 시각과 위젯의 `M월 d일 HH:mm 기록` 표기는 바꾸지 않는다. 이유: 방금 한 기록인지 한눈에 알 수 있어야 한다.
- **참여자 표시 이름:** 프로필 이름이 아직 없는 계정이 초대로 참여할 때만 로그인 계정 이름(Google 계정 이름, Apple은 첫 승인 때 받은 이름을 기기 메모리에서만 사용)을 한 번 채운다. 기존 이름은 덮어쓰지 않고 설정에서 바꿀 수 있다. 인사말은 서버 기본값 `가족`을 이름 없음으로 다룬다. 이유: 이름을 따로 묻지 않아도 가족 목록과 기록자에 `가족` 대신 실제 이름이 보이게 한다.
- **첫 차량 등록 간소화:** 사전 `차량 번호 중복 확인` 단계를 없앤다. 등록 시트는 차량 번호·차량 별명(기본 `우리 차`)·내 이름(로그인 계정 이름으로 미리 채움, 수정 가능) 세 칸이다. 번호 형식과 중복은 등록할 때 서버가 확인하고, 오류는 번호 칸 아래에 보인다. 아파트 이름은 묻지 않고 `우리 아파트`로 보내며 설정 → 우리 주차장에서 바꾼다. 이유: 서버 고유 제약이 이미 중복을 막으므로 별도 확인은 단계만 늘린다. 서버의 `check_vehicle_plate` RPC는 그대로 둔다.
- **로그인 화면 문구 축소:** 패널 제목·설명과 로그인 버튼 아래 안내를 뺐다. 실제 서버에 연결된 빌드의 로그인 화면에서는 체험 진입 전 `이 기기에만 저장` 안내가 없고, 체험 중 상단 안내는 유지한다. 누른 로그인 버튼에만 진행 표시를 한다. 이유: 작은 화면에서도 로그인 버튼이 첫 화면에 보여야 한다.
- **가족 초대와 참여:** 초대는 한 사람용 1회·24시간 그대로다. 초대 시트는 `초대 링크 공유`가 주 동작이며 48자리 코드 원문은 화면과 공유 메시지에 넣지 않고 `코드 복사`로만 제공한다. 초대 링크로 들어온 가족은 로그인 뒤 첫 카드의 `가족 차량에 참여하기`를 한 번 눌러 참여한다(자동 가입 아님). 사용했거나 만료된 초대는 안내 후 지우고 일반 카드로 돌아간다. 이유: 긴 코드를 읽거나 다시 붙여넣는 단계를 없앤다.
- **설정에서 차량 찾기 전용 항목 제거:** `차량 찾기 표시 사용` 스위치와 기본 시간 칩을 없앤다. 시작·종료·1/2/4/8시간 선택은 `차량 찾기 표시` 시트 한 곳에서 한다. 시작은 기기 표시를 먼저 띄우고 서버 설정(`live_enabled`, `preferred_live_minutes`)은 뒤에서 기록하며 실패해도 표시에 영향을 주지 않는다. 이유: 같은 기능을 두 곳에서 켜고 고르게 하지 않는다.
- **`위젯 설정` 바로 가기 제거:** 홈 위젯 배너에는 `추가 방법 보기` 하나만 남기고 안내 창에는 `닫기`만 둔다. 배너는 첫 주차 기록이 생긴 뒤에만 보인다. 안내는 설정의 `홈 화면 위젯` 줄에서도 열 수 있다. 이유: 정사각형 위젯에는 앱 안에서 설정할 항목이 없다. 2026-11-02의 '앱 내부 설정 바로 가기' 항목을 대체한다.
- **같은 사용자의 앱 재시작은 네이티브 정리를 건너뛴다.** 마지막으로 정리가 확인된 사용자 id(`carcar.session.user`)가 지금 세션과 같으면 위젯 스냅샷·차량 찾기 표시·알림 등록을 지우지 않는다. 로그아웃·계정 삭제·계정 변경·체험 시작은 지금처럼 정리하며, 이 값은 정리보다 먼저 지우고 정리 성공 뒤에만 다시 기록한다. 이유: 앱을 다시 켤 때마다 본인의 위젯 위치와 차량 찾기 표시가 사라지고 신호 없는 곳에서는 빈 채로 남았다.
- **조회·저장 제한 시간과 멱등 키 재사용 범위:** 앱은 조회 12초·저장 15초에 기다림을 끝내고 일반 오류로 안내하며, 서버 요청 자체도 15초에 중단한다. 같은 입력의 재시도는 직전 시도 후 2분 안에서만 같은 멱등 키를 다시 쓰고, 그 뒤에는 새 키로 새 기록을 만든다. 시간 초과로 포기한 요청이 나중에 성공해도 키는 지우지 않는다. 이유: 멈춘 연결에서 저장 창이 잠기지 않게 하고, 늦게 도착한 옛 요청이 다음 주차를 삼키지 않게 한다. 2분 뒤 재시도는 같은 위치의 기록이 한 건 더 생길 수 있으나 새 주차가 사라지는 것보다 안전하다.
- 첫 불러오기가 실패하면 `새 차량 등록` 카드 대신 `주차 위치를 불러오지 못했어요` / `다시 시도`를 보인다. 등록·참여 카드는 불러오기에 성공했고 차량이 없을 때만 나온다. 이유: 이미 차를 등록한 가족에게 새 계정처럼 보이지 않게 한다.

## 계정 삭제의 세션 고정과 Apple 연결 해제 · 2026-11-06

- 삭제 작업은 처음 확보한 Supabase 사용자·bearer에 고정한다. 서버에서 최신 연결 identity를 조회하고 Apple 계정이면 네이티브 자격만 재요청한다. 재인증으로 Supabase 세션을 교체하지 않으며, 계정 전환 뒤 이전 삭제 작업을 재개하지 않는다.
- `apple-disconnect` Edge Function은 Supabase Auth 사용자 검증 후 Apple 코드를 교환한다. 고정 JWKS의 RS256 서명·issuer·audience·시간·subject·nonce를 확인한 뒤 반환 토큰을 철회한다. DB 삭제와 service role 권한을 함수에 부여하지 않고 Apple 토큰도 보관하지 않는다.
- 자동 연결 해제 불가·서버 미설정·재인증 필요 오류에서만 사용자가 별도로 선택한 계정 삭제와 수동 연결 해제 안내를 허용한다. 사용자 취소·세션 변경·identity 불일치·서명 검증 실패는 삭제를 중단한다.
- 앱은 최초 bearer로 `delete_my_account`를 호출하고 서버 성공 뒤 같은 세션만 정리한다. 삭제 완료에 일반 로그아웃 콜백을 재사용하지 않으며 오래된 auth 이벤트가 새 계정을 지우지 않게 한다. 서버 삭제 성공 뒤의 로컬 로그아웃 네트워크 오류는 삭제 실패로 보고하지 않는다.
- 앱·Edge 로컬 검증은 완료했으나 키 등록·서버 배포·실제 Apple 인증/철회·실제 계정 삭제는 별도다. 최신 진행 상태는 [인계 문서](APP_STORE_HANDOFF.md), 운영 계약은 [서버 함수 배포 문서](../supabase/deployment/APPLE_SIGN_IN.md)를 따른다.

## Flutter 업그레이드와 iOS scene 전환 · 2026-11-06

- Xcode 27.2로 빌드한 앱이 iOS 27.2에서 UIScene 생명주기 누락으로 Dart 실행 전에 종료됐다. 사용자가 Flutter 업그레이드를 승인해 개발 기준과 공개 저장소의 세 CI workflow를 Flutter 3.47.9 / Dart 3.13.7로 맞췄다. 새 로컬 SDK는 `~/development/flutter-3.47.9`이며 이전 3.35.4 SDK는 보존한다.
- `Info.plist`에 단일 scene을 선언하고 `FlutterSceneDelegate`를 사용한다. 플러그인·네이티브 채널 등록은 implicit engine 초기화 시점으로 옮겼으며, 공유 화면·Apple 인증은 활성 scene의 key window를 사용한다.
- 고정된 `app_links` 6.4.1은 cold scene 링크를 직접 처리하지 않아 초기 URL·웹 활동만 별도로 전달한다. warm 링크는 Flutter의 기존 AppDelegate 플러그인 전달 경로를 사용한다. 추후 플러그인 갱신 시 별도 전달의 필요성과 중복 여부를 다시 확인한다.
- SDK가 생성한 Swift Package Manager 연결을 유지하고 `flutter_secure_storage` 9.2.4에는 CocoaPods fallback을 사용한다. 이 플러그인의 SwiftPM 미지원 경고는 남아 있으며, 이번 작업에서 플러그인 버전은 올리지 않았다.
- 로컬 Simulator 빌드가 성공했고 컴파일 결과의 앱 iOS 15.0·위젯 17.0을 확인했다. 네이티브 실행·링크·실제 인증 검증 결과는 [인계 문서](APP_STORE_HANDOFF.md)를 따른다. 이번 업그레이드는 새 TestFlight 배포나 App Store 제출 완료를 뜻하지 않는다.

## 정사각형 위젯 시안 확정 · 2026-11-06

- 사용자는 정사각형 모델만 사용하기로 했고, 시간 표시를 수정한 두 번째 시안 묶음의 **1번(상단 기록 시각)**을 선택했다. 기준 이미지는 `docs/design/square-widget-time-variants-2026-11-06/01-top-caption.png`다. 첫 시안 묶음의 1번과 구분한다.

## 현재 제품 기본값 · 2026-11-06 (2026-11-11 갱신)
- 첫 아파트 층수: F1/F2/F3/F4/F5/B1/B2/B3/B4/B5 (설정에서 변경 가능)
- 기본 구역: A/B/C/D/E/F/가/나/다/라/마/바 (설정에서 변경 가능)
- 번호: 선택 입력, 최대 20자
- 차량 수: 계정당 한 대. 최초 등록자는 소유자, 다른 가족은 소유자의 초대로만 참여. 정규화 차량번호는 DB에서 고유함
- 초대 코드: 192비트 난수의 48자리 hex, 24시간 유효, 한 사람용 1회 사용. 초대 시트는 링크 공유가 주 동작이고 코드 원문은 화면·공유 메시지에 넣지 않으며 `코드 복사`로만 제공. 받은 초대는 로그인 뒤 버튼 한 번으로 참여하며 자동 가입하지 않음
- 새 차량의 아파트 이름: `우리 아파트` (설정 → 우리 주차장에서 변경), 차량 별명 기본 입력값 `우리 차`
- 층수 앱 아이콘: iPhone은 기기별 스위치·기본 OFF, Android는 자동
- 사진 서버 저장: 기본 OFF (OCR 후 원본 기기에서만 처리)
- 실시간 표시: 기본 OFF, 명시적 사용자 활성화(차량 찾기 표시 시트에서 시작·종료·시간 선택)
- 본인 주차 기록 알림: 기본 OFF
- 야간 알림 제한: 기본 OFF
- 사용자 표기 시간대: 기기 로컬

## 주의할 미확정 사항
- 실제 아파트 기둥 표기의 형식(B2+C24가 한 사진에 나오는지).
- 실기기 Android Now Bar 지원 모델/OS 조합.
- Google OAuth의 실제 로그인 왕복, 가족 간 공유·푸시, 최신 네이티브 변경의 실기기 검증은 릴리스마다 확인. 플랫폼 설정 완료나 App Store 심사 통과를 코드 구현만으로 확정하지 않음.
- 공개 App Store 배포 전에 소셜 로그인 관련 심사 요건과 Apple 로그인 추가 필요성을 검토. 현재 Google 로그인 구현을 공개 배포 승인으로 간주하지 않음.

## 변경 이력 · 2026-11-02

- 초기 이메일/비밀번호 가입 화면을 Google 로그인으로 대체. 기존 계정의 복구 링크 처리만 호환 경로로 남김. 새 가입 흐름에 SMTP나 문자 인증을 요구하지 않음.
